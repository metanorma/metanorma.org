== Metanorma CLI 1.18.7

Metanorma CLI 1.18.7 is released as the first stable release of the 1.18 line. The release rebuilds the substrate of the toolchain: the bibliography and document-identifier libraries are consolidated into two model-driven monogems, the XML serialization layer is replaced in full, a typed document model becomes the basis for a new generation of output paths, and the platform moves to Ruby 4.0. `metanorma-cli 1.18.7` is on RubyGems, and `metanorma/metanorma:1.18.7` (with `:latest`) is on Docker Hub with the identical dependency set.

== Notable changes

=== pubid 2.0: document identifiers as one model-driven monogem

The pubid family of eleven gems (pubid-iso, pubid-bsi, pubid-iec, pubid-ieee, pubid-itu, pubid-iho, pubid-nist, pubid-jis, pubid-ccsds, pubid-cen and pubid-etsi) is consolidated into a single pubid 2.0 monogem, and the parser behind every identifier is now driven by declarative models on lutaml-model rather than hand-written rule code.

Users can cite far more than before. One gem now understands the identifier syntax of over sixty issuing bodies: the previous eleven, joined by Adobe, AMCA, ANSI, arXiv, ASHRAE, ASME, ASTM, BIPM, BSI Preferred Publications, Calconnect, CCSDS, CEN/CENELEC, CIE, CSA, DOI, EASC, ECMA, ETSI, the EU, EVS, GB, GOST, IALA, IANA, ISBN, JCGM, OASIS, OGC, OIML, OMG, Plateau, SAE, 3GPP, UN, W3C, WMO and XSF. Identifiers render as citations, as URNs, and through automatic format detection, from a single ruleset maintained in one place.

=== relaton 3.1: bibliographic metadata as one model-driven monogem

The same consolidation happened on the bibliography side: thirty relaton gems (relaton-cli, relaton-render, relaton-bib, relaton-iso, relaton-iec, relaton-ieee, relaton-itu, relaton-iho, relaton-nist, relaton-bsi, and the rest) are folded into relaton 3.1, a monogem whose bibliographic entities are lutaml-model classes with round-trippable serialization.

Relaton 3.1 ships thirty-seven bibliographic sources in one gem, covering the same bodies as pubid plus IEEE, IETF, W3C, 3GPP, and ISO 639 language and script registries. Reference resolution, the rendering pipeline that was relaton-render, and the command-line interface that was relaton-cli are part of the one library, so a citation retrieved by any flavor renders through the same code path as every other flavor.

=== The leptris serialization family replaces Nokogiri

Metanorma's XML handling moves from Nokogiri, which binds to libxml2, to the leptris family: leptris for XML, HTML and XSLT, yeptris for schema validation, and moxml 0.6 as the document-adapter seam that the whole stack now programs against. Nokogiri remains in the dependency tree only through third-party libraries; Metanorma's own gems no longer call it.

On a one-megabyte Metanorma document, a parse, full node walk, and serialize round trip through leptris runs 2.46 times faster than through Nokogiri (1.35 ms versus 3.32 ms per iteration, benchmarked in the released container with the default parser settings), with the advantage growing with document size. On a 170-kilobyte document the round trip is 1.18 times faster. Resident memory is comparable across both engines. The schema-validation path, previously handled by shelling out to the Java-based Jing, now runs in-process with native diagnostics, which removes a JVM dependency from validation entirely.

=== A typed document model, and what it is for

metanorma-document 0.5 introduces a round-trippable, lutaml-model-typed model of the Metanorma XML document. It is the basis of the toolchain's second stage: processors that read a compiled document and emit output, instead of parsing AsciiDoc source again. The first users of that model are the new output engines in this release (uniword for DOCX, the STS validator, and the flavor taste system for HTML themes), and features such as update units for amendment and revision records are declared against it.

metanorma-mirror 1.0 ships on the same model, providing the document-mirror system used for publication mirroring.

=== Word output from the document model (technology preview in ISO)

uniword 1.7 generates DOCX from the document model, and it is the engine behind the new ISO DOCX output, which is available in alpha. The previous DOC (MHTML) output remains the submission-grade format for ISO documents; uniword DOCX is the path under active development, and feedback from ISO document authors is welcome while it matures.

=== ISO/NISO STS as a validated pipeline

The STS gem reaches 0.6 with the NISO JATS model in the stack, and STS generation is now a validated pipeline: documents converted to ISO/NISO STS (standard-tagged XML with MathML 3) are checked against the NISO STS XSD as part of the conversion. STS consumes the presentation XML produced by the toolchain, so the tagged output carries the same content users see in HTML and PDF.

=== The LutaML stack

lutaml-model absorbs one hundred and fifty-seven releases in this window (0.8.19 to 0.8.176), hardening parse materialization and content models across the board. The LutaML language gains two new surfaces, lutaml-jsonschema and lutaml-openapi, alongside lutaml 0.11. lutaml-uml reaches 1.0.4 and its Enterprise Architect front end ea 0.6.149, which now maps enumeration literal initial and code values onto Lutaml::Uml. metanorma-plugin-lutaml 0.7.81 stages document figures eagerly and by stable basename, so large figure sets render completely.

=== Correctness in the renderers

The first stage of the toolchain, the renderers users depend on today, is corrected on several fronts. Word output restores inline formulas as native Word equations and returns block content that was dropped: notes after tables, term definitions, notes to entry, and annex subclause notes, at style parity with the 1.17 series. Bibliographies terminate according to each flavor's own punctuation rules, and reference lists carry a single Contents heading. Duplicate identifiers, a class of defect that previously could abort PDF rendering late or truncate it silently, now fail the build at the correct stage. ISO draft-stage references (DAM and AMD) survive rendering, and the ISO flavor's DOC path routes through the maintained isodoc chain. The IHO flavor gains the publisher cover identity, and the IALA corpus (twenty-five documents) compiles end to end under the released toolchain.

=== Ruby 4.0 and the frozen image

The toolchain line is Ruby 4.0: the Docker image runs Ruby 4.0.7 on both the Debian and Alpine variants, and the dependency lock has dropped the gems that Ruby 4.0 provides by default. The image also moves to fontist 3.0 on the formulas v3 line, mn2pdf 2.74, and mnconvert 1.89. In total, sixty-two gems leave the dependency set and thirty-three join it; the complete ledger is published in the wave tracker (metanorma/release-engineering#7).

== Fixed

* Bibliography terminators honor flavor i18n punctuation; the trailing-period drift between builds is gone.
* ISO citation rules no longer crash on string cross-references; the uniqueness rule no longer mis-flags mirrored front-matter clauses, and documents that previously aborted multi-document site generation compile.
* Bibliography rendering can no longer emit one element identifier twice, which Apache FOP rejects as fatal.
* Figure sets in LutaML documents render completely; EMF and SVG output gains pattern-fill fixes (emfsvg 0.1.5).
* JIS documents parse again (parsanol 1.5, now with native platform builds).

== Compatibility notes

The toolchain line is Ruby 4.0. Projects pinned to Ruby 3.3 should remain on the 1.17 series until their runtime moves. Projects pinning individual relaton-* or pubid-* gems should pin `relaton` and `pubid` instead, since the family gems no longer exist. The un, m3aawg and gb flavors return to the default image bundle; the OIML flavor is new in this line.

== Upgrading

```
gem install metanorma-cli -v 1.18.7
docker pull metanorma/metanorma:1.18.7     # or :latest
```

A plain `bundle update` resolves without prereleases. The full dependency ledger of the image is in the wave tracker (metanorma/release-engineering#7).

=== Packed distribution

The tebako-packed distribution continues alongside the gem and Docker images: packed payloads for the 1.18.7 prerelease line shipped through the window (packed-metanorma v1.18.7.pre.20261121 of 2026-11-22, carrying fourteen signed payload images across the supported platform triplets). The stable 1.18.7 packed payload is cut on the same packing pipeline after the gem release; the packed install command from the 1.17 series is unchanged, and users of the packed distribution can stay on the packing channel's release feed to pick up the stable payload when it lands.
